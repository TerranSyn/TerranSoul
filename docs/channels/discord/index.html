Discord

Discord's bot API is architecturally the opposite of Telegram's: instead of a scheduler-driven poll, a bot holds one persistent WebSocket connection ("the Gateway") open for its whole lifetime.

Status & capabilities

Bidirectional. A supervisor connects to the Gateway at host boot, identifies once, heartbeats on the interval Discord dictates, and receives message events the instant they happen — no polling delay. If the connection drops, the supervisor reconnects with backoff, resuming the session where possible instead of re-identifying from scratch. Outbound sends are a normal REST POST to {base}/channels/{id}/messages with Authorization: Bot <token>.

Quickstart

Everything below happens in two places: the Discord Developer Portal (steps 1–4, once) and TerranSoul's Brain → Channels tab (step 5).
  1. Create an application at the Discord Developer Portal → Bot tab → Reset Token and copy the token (it is shown once).
  2. On the same Bot tab, enable the MESSAGE CONTENT INTENT toggle. Without it the bot connects but Discord withholds message text, so nothing ever reaches the brain.
  3. Generate an OAuth2 invite URL (OAuth2 → URL Generator) with the bot scope and View Channels/Send Messages/Read Message History permissions, open it, and add the bot to your server.
  4. Get the numeric id of the channel you want it to post in (right-click the channel → Copy Channel ID; Developer Mode must be on under Discord Settings → Advanced).
  5. In TerranSoul: Brain → Channels → Discord card — paste the token and channel id, Save, then flip the Enabled toggle. The gateway connects within ~5 seconds (watch the status dot). Optionally set Allowed senders to your own user/channel ids so strangers get a polite refusal, and fire a Test send.

Message the channel from Discord — the bot replies through the same brain pipeline as the desktop chat, with one isolated conversation per Discord channel (session tag channel:discord:<channel id>).

Constraints: local-only mode blocks all channel egress; run only one TerranSoul instance per bot token.

Auth setup (headless / programmatic)

The Channels tab drives these same commands; a headless install can call them directly:

channel_save_credential(
  channel: "discord",
  json_str: '{"token": "<bot token>", "chat_id": "<default channel id>"}'
)
channel_config_set(channel: "discord", key: "enabled", value: "true")

Config

KeyMeaning
channels.discord.enabledMust be true for the gateway supervisor to run. UI: the Enabled toggle.
channels.discord.allowed_sendersComma-separated allow-list of channel/user ids permitted to reach the brain; everyone else gets a polite refusal. Empty/absent = allow all (an empty list can never lock you out). UI: Allowed senders.
channels.discord.max_message_lenOutbound cap in Unicode code points (default 2000 — Discord's limit). Longer replies are split into sequential messages at paragraph/line/word boundaries instead of being rejected whole. 0 disables splitting.
channels.discord.dedup_cache_sizeHow many recent message ids are remembered to drop gateway-redelivered duplicates after a reconnect (default 512; 0 disables).
channels.discord.intentsGateway Intents bitmask requested at identify (default 37376 = guild + direct messages + message content). The portal's MESSAGE CONTENT toggle must ALSO be on.
channels.discord.gateway_urlOptional override of the live wss://gateway.discord.gg endpoint — mainly a test seam, not something you'll normally set. Not editable from the UI.
channels.discord.base_urlOptional REST API base override. Not editable from the UI.

Troubleshooting

  • Bot connects but never sees messages — check the Message Content Intent is enabled in the Developer Portal; without it, Discord silently strips message text from the events the Gateway sends.
  • Repeated reconnects — normal in small numbers (Discord Gateway connections do drop); persistent reconnect loops usually mean an invalid/revoked token.
  • "chat_id has no destination" — no default channel id saved and no recipient passed to channel_send.
  • Send failures — the Channels tab's test-send surfaces a structured detail line (attempted= / observed= / likely_cause= / try=): 401 = token invalid/revoked, 403 = bot not in that channel or missing Send Messages, 404 = wrong channel id.
  • Replies stop mid-conversation with local-only mode on — local-only mode blocks all channel egress by design.
