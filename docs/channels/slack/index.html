Slack

Same shape as Discord — one persistent WebSocket, events pushed instantly — but Slack's wire protocol needs two secrets instead of one, and the socket URL is a single-use ticket rather than a fixed address.

Status & capabilities

Bidirectional over Socket Mode: no public URL or webhook endpoint required, which makes it usable behind NAT/firewalls without any port forwarding. Every events_api envelope the socket receives must be acknowledged within 3 seconds or Slack redelivers it; there's no session-resume across a reconnect — a fresh apps.connections.open call is made every time. Outbound sends are a normal REST POST.

Auth setup

  1. Create an app at api.slack.com/apps.
  2. Under Socket Mode, enable it and generate an App-Level Token with the connections:write scope — this is the xapp-… secret.
  3. Under OAuth & Permissions, add the chat:write scope (and channels:history/im:history if you want it to see channel/DM history) and install the app to your workspace — this gives you the Bot User OAuth Token, the xoxb-… secret.
  4. Under Event Subscriptions, enable events and subscribe to message.channels (and/or message.im for DMs).
  5. Invite the bot to the channel you want it to use (/invite @yourbot), and get that channel's id.
  6. Save the credential — both tokens go in the same JSON blob:
channel_save_credential(
  channel: "slack",
  json_str: '{"token": "xoxb-...", "app_token": "xapp-...", "chat_id": "<default channel id>"}'
)

Then flip channels.slack.enabled to true.

Config

KeyMeaning
channels.slack.enabledMust be true for the Socket Mode supervisor to run.
channels.slack.base_urlOptional Slack REST API base override.

Troubleshooting

  • "needs the App-Level token" — you saved only the bot token; Socket Mode needs both token (xoxb-…) and app_token (xapp-…) in the same credential blob.
  • Bot connects but sees no messages — check the Event Subscriptions are actually turned on and subscribed to the right event types, and that the bot has been invited to the channel.
  • Frequent reconnects — each Socket Mode connection is single-use by design; the supervisor opening a fresh connection periodically is normal, not a bug.
