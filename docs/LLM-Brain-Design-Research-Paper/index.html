Memory as a First-Class Architectural Layer: in a controlled taught-solution setting, delivery reliability — not model capacity — bounds a weak agent on Zork I.

Holding the local effective-4B model, gemma4:e4b in this study, the taught solution stored in the external memory server, and the critic fixed, the factor that moved the agent to a deterministic 350/350 score on Zork I was not model size. It was how reliably the chosen move reached the game engine.

Scope of the result
  • The paper isolates delivery reliability as an agent-performance variable.
  • The 350/350 result is a taught-solution delivery-reliability demonstration: a correct strategy is held fixed and only delivery reliability is varied. The model's unaided (AGI-pure) score is 10–20.
  • Three claims are kept strictly apart: a memory lift (§4.3), a delivery-reliability result (§4.4), and an economic distillation-through-memory architecture (§5).

AbstractWhat this paper measures

Whether an LLM agent's long-term memory belongs inside the model or outside it is an open architectural question, and one that the 2025–2026 literature treats as central. A recent survey formalises agent memory as "a write–manage–read loop tightly coupled with perception and action" and argues that "memory … is what turns a stateless text generator into a genuinely adaptive agent" [15]. We study the question with a deliberately weak local model — gemma4:e4b, an effective-4B edge model whose E4B configuration uses per-layer embeddings (so its effective parameter count is smaller than its total footprint), served by Ollama — wired to the system under test (TerranSoul's external memory server, referred to as "the brain" or "the external memory server" throughout), reached over the Model Context Protocol (MCP), and measured on Zork I through the Jericho Z-machine interface [11]. The external memory server is evaluated alongside two controls and a frontier reference (Claude Opus 4.8, ZorkGPT ep120), with the memory substrate as the sole independent variable.

The task is hard by design: the TALES suite reports that "even the top LLM-driven agents fail to achieve 15% on games designed for human enjoyment" and that "Zork1 still proves an insurmountable challenge even for modern state-of-the-art LLMs" [14]. We run the upstream stickystyle/ZorkGPT agent — an existing system we did not author — unmodified and swap only its memory/knowledge managers, leaving the substrate as the sole variable. We report: (1) stability — 1 682 memory operations across four canonical episodes at 0 errors, and 6 456 at 0.17% in a later run; (2) four failure classes — silent ingest, mis-scoped reflection, frozen prompts, grammar-without-strategy seeds — each fixed at the brain layer, the first being the concrete face of the survey's warning that "one bad write can pollute the store for many steps downstream" [15]; (3) AGI-pure lift — with no task seeds, the external memory server raises the same 4B from 0 to 10–20; (4) the reliability result — holding model, knowledge and critic fixed, only delivery reliability separates a non-deterministic 73/177 from a deterministic 350; (5) a frontier reference — Claude Opus 4.8 reaches 350 by recall, 50 by cold reasoning, against a public frontier-scaffold best of 115; and (6) AGI-pure self-improvement on a 12B model — under a fully frozen harness and AGI-pure zero-game-specific-seed discipline, the brain's own runtime learning drove a gemma4:12b-it-qat from ep1=10 to ep2=20 (2×), 2 355 MCP calls, 0 errors, via a two-iteration band-separation fix to a single generic planner-bonus seed constant (§4.3b) — a single lucky episode (the modal AGI-pure Zork I result is 10→10); a later re-validation on a persistent brain reached a peak episode 45, but de-confounded per-run on a fresh task-naïve brain the cross-episode result is ~15 (across-run accumulation, not repeatable single-run self-improvement, §4.3d). The pattern separates three claims: the system under test lifts the unaided model; with a strategy held fixed, delivery reliability — not added capacity — was the binding constraint; and the system under test enables an economic distillation through memory. We position delivery reliability as a third performance axis alongside retrieval quality and model capacity. On the orthogonal retrieval axis, the same external memory server is competitive or leading on four public memory benchmarks against published baselines (agentmemory, MemoryPalace), with retrieval holding R@10 64.0% at 100k-document scale and store operations meeting interactive latency/token budgets to the million-entry tier (§4.6–4.7). Scope is explicit: this is a single-ROM, single-model-family demonstration; the LLM-arm matched controls and cross-game n = 2 trials are reported (§4.3c–4.3d, the cross-game lift reproducible but its deeper climb high-variance), and broader model families and the full game surface remain a deliberate scope boundary.

01 · IntroductionInside the model, or beside it?

A capable agent must remember what it learned in the last episode, what failed in the last room, and what lies beyond its context window. Du's 2026 survey puts it plainly: without memory, "every Monday morning it rediscovers the directory layout, re-reads the same README" [15]. Two architectures answer the need. The model-internal approach grows the context window or fine-tunes weights; the model-external approach factors memory into a queryable store the agent reads and writes through tools — the lineage of MemGPT/Letta [2], Mem0 [1], HippoRAG [4], and temporal knowledge-graph systems such as Zep/Graphiti [10], now surveyed from several angles [15,31,32,33].

The system under test takes the external-memory approach: a Rust memory server with a six-signal hybrid retriever (BM25/FTS5 + dense HNSW + reciprocal-rank fusion, k=60) and a typed knowledge graph, exposed to any client over MCP. We ask the sharpest version of the question — does an external memory server help a model too small to hold the task in its head? A 4B model is a stringent probe, so the answer is legible either way. We measure on Zork I because text adventures, as BALROG argues, demand "intricate interactions, advanced spatial reasoning, long-term planning, and continuous exploration of new strategies" [13], and current models fall far short [13,14]. That a 4B (gemma4:e4b) scores near zero unaided is expected; it is what makes the system's measurable lift, and the reliability result, meaningful rather than trivial.

02 · Related workWhere this sits

Agent memory and 2025–2026 surveys. The external-memory lineage runs from MemGPT/Letta [2] through Mem0 [1] — whose LLM-arbitrated conflict resolution the system under test adopts at its graph layer [20] — to HippoRAG [4] and spatial schemes [3]. Du formalises memory as a "write–manage–read loop" [15]; From Storage to Experience traces three stages toward "the ultimate goal of continual learning" [32]; a unified survey organises methods by construction, update, and query [33]; and the Mnemonic Sovereignty security survey calls agent memory "malleable, rewritable, and socially propagating" [31] — context for our §4.2.

Benchmarks. LoCoMo [34], LongMemEval [35], and BEAM anchor the field; MemoryAgentBench [22] grounds evaluation in cognitive science (retrieval, test-time learning, long-range understanding, selective forgetting) and AMA-Bench [23] targets long-horizon agentic memory. Du reports a sobering gap: "models that score near-perfectly on LoCoMo plummet to 40–60% in MemoryArena" [15] — which is exactly why we report both retrieval (§4.6) and acting (§4.1–4.4).

Retrieval and graph memory. The system's retriever fuses lexical and dense channels with reciprocal-rank fusion and applies Contextual Retrieval [8] and HyDE [9], the latter gated per query class [20]. The graph layer follows GraphRAG's Leiden lineage and the typed-edge designs of Zep/Graphiti [10], MAGMA [24], and PersonalAI [25]. Singh, Ehtesham et al. survey the move to agentic retrieval — agents that "leverage agentic design patterns reflection, planning, tool use, and multi-agent collaboration" — and name "Memory Management and Long-Term Adaptation" and "Safety, Trust, and Governance" as open challenges [26], the territory of our §4.2 and §4.4.

Reasoning, self-evolution, skills. ReAct [5] interleaves reasoning and acting; Reflexion [6] adds verbal self-feedback; Voyager [7] accumulates a skill library; AutoSkill [27] and RL-with-skill-library frameworks [28] extend this. Our room-scoped reflections (§4.2) are Reflexion with spatial scope; our taught skill (§4.4) is a Voyager-style library entry — but we separate having a skill from executing it, which is what exposes the delivery axis.

Games and text-adventure agents. Jericho exposes 55 interactive-fiction games with ground-truth state and scores [11]. BALROG reports broad struggle on hard tasks [13]; TALES unifies Jericho, ALFWorld, ScienceWorld and TextWorld and finds that "all models struggle to reason across extremely long-horizon contexts where important information is sparsely scattered throughout," that "Claude models demonstrate the best overall performance," and that Zork I remains "insurmountable … even for modern state-of-the-art LLMs" [14]. TextQuests [29] and Dual-Scale World Models [30] extend the line. The upstream agent we run, ZorkGPT [12], peaks at 115/350 with a frontier model — our scaffold reference (§4.5).

03 · MethodsThree arms, one variable

We run upstream ZorkGPT [12] against Jericho's zork1.z5 [11] in a sealed Docker image. Agent, critic, extractor and strategy-generator are all the same model (gemma4:e4b); seed, temperature and ROM are fixed. Only the substrate changes:

ArmMemory + knowledge substrate
nonebare LLM, episode-local only
zorkgpt-defaultZorkGPT's own managers (the upstream thesis)
terransoul-brainexternal memory server over MCP — brain_search reads, brain_ingest_lesson writes, typed KG edges

The external memory server runs as a separate OS process; the bridge speaks MCP JSON-RPC 2.0 over a real TCP boundary (container → host), bearer-token authenticated, with explicit error accounting — the same transport a production client uses. The bridge derives memory importance from game signals rather than text heuristics (score_delta>0 → 10; first visit → 7; a 3-repeat loop → a dead-end principle; death → a fatal memory), writes structured content the KG auto-extractor turns into typed edges, and retrieves principles before episodics so cross-episode rules are not buried. Map adjacency is promoted into a memory_edges graph via brain_add_edge; a probe confirms Living Room —exits_via_west→ Kitchen survives restarts and is queryable by any client.

A sequence of domain-agnostic perception/decision gates was added at the bridge layer, each validated by a sub-10-second reproduction first: ID-keyed mapping by Z-machine location_id, valid-exit validation, id-based loop-breaking and exit-pruning, one-shot light-acquisition, and a delivery rule that banks score-bearing items over junk (value learned from the score signal, never a hardcoded list). A standing AGI-purity rule forbids seeding Zork maps, routes, or vocabularies, enforced by a grep gate. The single exception is the labelled demonstration of §4.4, whose taught solution is demo-only, never written to the memory seed (verified by grep), and gated behind a runtime flag.

04 · ResultsStability, four lessons, and the reliability result

4.1 Architectural stability

Two canonical 2-episode × 100-turn runs executed 1 682 MCP operations with 0 errors while the external memory server concurrently served the desktop app for four hours; the longer §4.4 run logged 6 456 operations at 0.17%.

4.2 Four agent-memory failure classes

  1. Verify, don't trust. Every brain_ingest_lesson had silently stored zero rows for the bench's history — the client read a structured error envelope as success. This is the concrete form of Du's warning that "one bad write can pollute the store for many steps downstream" [15]; here the bad write was no write, undetected. A 14-line fix plus a per-episode retrievability probe closed it.
  2. Reflections require spatial scope. Per-room reflections tagged loc_<id> are surfaced by the next episode's room-scoped retrieval exactly when the agent re-enters the room — Reflexion [6] at the right granularity for an embodied agent.
  3. The prompt is a snapshot, not a stream. Upstream builds the system prompt once at episode start; a lantern found at turn 11 was never seen. A reload_knowledge_base() push fixes it — possible only because the bridge, not the model, owns the prompt.
  4. Grammar is not strategy. A seed listing verbs without strategy left the agent examining a closed mailbox for 100 turns. Replacing the seed is a brain_ingest_lesson call, not a fine-tune.

4.3c Cross-game generalisation: brain-mediated self-improvement transfers, bounded by the model's planning depth (n = 2)

Generalising the §4.3b result beyond Zork I to detective.z5 and 905.z5 returned a sharper answer. The unchanged bridge did not transfer cleanly: it carried three generic bookkeeping defects that only surface on games whose death/blocker structure differs from Zork I. Each was repaired brain-side — the learning signal is written to and read from the MCP brain (brain_ingest_lesson → brain_search), with no game content, no seeds (mcp-data/shared/memory-seed.sql byte-identical) and zorkgpt's zork_agent_patch.py left frozen: (1) origin/id-keyed death-aversion; (2) gate-state invalidation after a successful open/unlock; (3) open-first — a traversal that fails because the game itself names something "closed/locked" writes a generic "open it first" lesson the planner reads back to promote open <noun>. We label the repaired bridge harness v2; its three fixes are generic plumbing that routes the brain's own runtime memories (no room names, verb lists, or walkthrough — the AGI-purity grep gate passes). The §4.3b "harness and bridge fully frozen" statement applies to the Zork I 12B arms only; every row below is harness v2 and n = 1. Zork I is re-run under v2 as a no-regression control.

What transfers, and what bounds it. The clean win is Detective, where the bottleneck is memory: episode 1 died entering the restaurant (north, turn 4); the bridge wrote a death-aversion memory keyed to that room's location-id; episode 2 read it back (brain_search kind=death, 1 hit), avoided the fatal move, and survived to explore 18 rooms vs 4 and score 60 vs 20 — generalising §4.3b to a second game and a different mechanism. Where the bottleneck is the 12B's planning or the parser, the mechanism fires but the score does not move: on Zork I under v2 the open-first lesson opened the kitchen window and the agent reached the Living Room's treasures, yet the score held at the modal 10 (the §4.3b 10→20 was a single lucky episode; the modal AGI-pure Zork I result is 10→10). On 9:05 the open-first and gate-invalidation mechanisms fired repeatedly (open-first wrote a closed-blocker lesson and promoted open door on ~25 ep2 read-backs; gate-invalidation cleared a stale cardinal once) but could not unblock the true exit: open door triggers a parser disambiguation ("the front door or the bedroom door?") the 12B never resolved, so it kept opening the already-open bedroom door. Death-aversion never triggered (no death), and 9:05 awards essentially no score before completion, so both episodes scored 0 — an honest null whose bottleneck is the parser/planner, upstream of where the memory mechanisms can act. The 12B's mid-episode navigation stayed weak throughout (e.g. a ~60-turn revisit loop on Detective), itself on-thesis: the lift comes from externalised memory, not model competence.

Repeated trials (n = 2). A second series of each game (under the current harness) sharpens the picture and tempers the n = 1 Detective headline. Detective returned a flat 20 / 20 / 20 (vs the n = 1 20 → 60): the memory-lift to 20 is consistent, but the deeper cross-episode death-aversion climb to 60 did not reproduce — all three episodes walked into the same restaurant game-over (turns 4–7) and the death-aversion did not fire. The 20 → 60 win was a single favorable episode, the same high-variance regime as the Zork I 10 → 20; the reliable claim is the lift to 20, not the climb to 60. 9:05 reproduced its null (0 / 0 / 0), confirming the parser/planner bottleneck is upstream of memory — a robust null. Caveat: the re-runs use the current Zork-tuned harness and a shared Zork-loaded brain, so they are honest re-runs rather than clean isolated replications; a fresh-brain per-game replication would tighten the variance estimate further.

4.3d Self-improvement-stack re-validation: across-run accumulation breaks the modal-10 ceiling on a persistent brain (peak 45); the de-confounded per-run cross-episode result is ~15 (peak 20), AGI-pure (n = 3 × 9 runs)

§4.3b reported a single lucky doubling (10→20, n = 1) against a modal AGI-pure Zork I result of 10→10, and the future-work list carried the gradient-free self-improvement stack as implemented but bench-pending. We now report that re-validation. Across nine sequential 3-episode × 300-turn runs on gemma4:12b-it-qat (frozen stickystyle ZorkGPT actor + critic; the brain preserved across episodes so its own runtime learning accumulates), the modal-10 ceiling is broken at the run-series level: every run past the first carried at least one episode ≥ 20, four reached an episode ≥ 35, the best single episode reached 45 by closing — and surviving — the full underground-descent chain, and the most recent runs held the per-episode floor at 35 (every episode ≥ 35) as surface-treasure delivery became reliable. We de-confound this below: on a fresh task-naïve brain the per-run cross-episode result is ~15 (peak 20), so the peak-45 / floor-35 figures are an across-run accumulation effect on the persistent brain, not repeatable single-run self-improvement.

What broke the ceiling. The cap was never the turn budget — episodes reached the productive interior with turns to spare. It was a chain of generic, domain-agnostic harness controls (each a zero-game-token gate validated by a sub-10-second replica in benchmark/scripts/zork-bench/_repro_loopbreak_and_critic.py) composing with the brain's own runtime learning: a loop-breaker that escapes a dead-end oscillation via an untried frontier exit; a reflection risk lens — previously defined but unreachable — wired to the agent's own count of no-visibility outcomes, which finally generates the "satisfy the safety precondition before entering a state you cannot perceive" insight; a critic that retains such directiveless actionable insights; activating the carried light on entering the dark so the agent proceeds instead of dying or retreating; and the keystone, state-change-replay — a non-scoring prerequisite move that reveals new state (moving furniture uncovers a hidden trap door) scores 0, so the score-gated solution-move writer never persisted it and a later episode replayed the dependent descent without its precondition; recording the reveal as a replayable per-room move breaks that bootstrap deadlock. The prerequisite was discovered by the agent at runtime and recorded by the brain (v15 ep3), then replayed in later runs — none seeded. A RESIDENT richer-recall budget (the Fable-5 "resident mind deserves richer recall" treatment, scaled to the model's real context window) ensures the recorded prerequisite is retrieved alongside the scoring moves rather than crowded out.

Honest bounds. The result is high-variance: with n = 3 episodes per run, single-episode scores ranged 5–45 and per-run means 16.7–36.7, so individual-fix attribution is noisy (one band-priority change scored 20/35/25, was indistinguishable from its revert at 45/35/5, and was reverted on that evidence). The residual failure modes are the frozen actor's, not the memory substrate's: an episode either never reaches the house (lost in the forest/canyon region) or rushes the descent past an untaken lamp — the agent performs every sub-task (take and light the lamp, move the rug, open the trap door, descend, deposit treasures, survive the lit cellar) but cannot reliably chain them, and band-tuning to force the ordering trades one failure mode for another. As each survival fix landed the frontier deepened: a subsequent run descended past the lit cellar to the Troll Room — a combat encounter the frozen 12B does not execute (it died to the troll) — confirming that the memory mechanisms keep unblocking progress and the bound keeps moving to the next actor capability rather than the memory layer. This is on-thesis: the lift comes from externalised memory + generic controls, and the ceiling that remains is the weak model's multi-step planning and stochasticity, not the brain. AGI-purity held throughout — the bridge source carries zero game tokens (grep-gated), memory-seed.sql is unchanged, and every game-specific decision (the rug-move prerequisite, the descent route, the lit-cellar exploration) was authored by the brain at runtime.

De-confounding across-run accumulation from within-run cross-episode learning. The nine runs above share one persistent brain, so the 10 → 45 progression conflates two distinct effects: within-run cross-episode learning (ep1 → ep3 of a single 3-episode run) and across-run accumulation (the brain carrying a lucky runtime discovery — e.g. the v15-discovered rug-move prerequisite — into all subsequent runs). To isolate the former, we re-ran the identical configuration on a fresh, task-naïve brain per run (the canonical base seed, zero accumulated Zork rows). The clean cross-episode result is 10 / 10 / 15 then 10 / 20 / 15 (mean 11.7 → 15.0, peak 20 over six episodes): the agent reliably reaches the interior — the scenic-dead-end navigation trap that capped the saturated-brain runs vanishes on a clean store — but across six task-naïve episodes it never re-discovers the full rug → trap-door → lamp → cellar chain, so it never descends. The de-confounded measure is therefore consistent with the modal-10 / actor-bound thesis: the dramatic peak of 45 required across-run accumulation of a lucky one-time discovery, not repeatable single-run cross-episode self-improvement. This sharpens rather than overturns the result — externalised memory is a genuine performance axis (across-run accumulation is itself memory working, and removing the accumulated traps measurably improves navigation), but the binding constraint is the frozen 12B's inability to re-discover the multi-step chain from a clean start: the actor, not the memory layer. (We also note the methodological hazard this exposes: benching against a persistent developer brain let it accumulate to ~98% Zork episodic rows over many runs; the AGI-pure measurement is the isolated-brain one, and the across-run numbers should be read as an upper-variance envelope, not a repeatable per-run capability.)

Cross-model generalisation (memory-lift across architectures). To test whether the externalised memory lifts a different architecture, we ran qwen2.5:7b — a distinct model family from gemma — under the identical protocol with two arms (3 episodes × 300 turns each). Unaided (none arm) it scored 0 / 0 / 0, the classic fixation regime. Reading the same accumulated brain the 12B built, it scored a consistent 5 / 5 / 5. The lift is therefore real and generalises across architectures — the brain's runtime-learned knowledge is actor-legible (§3.3) — but its magnitude is bounded by the reading actor's planning depth: qwen-7B reaches a flat 5 where the 12B, reading the same accumulated store, reaches up to 45 (the across-run-accumulation peak; the de-confounded per-run 12B result is ~15, this §), and shows no cross-episode climb. This sharpens the central claim — the externalised memory is the portable asset, and what it buys is gated by the actor that must execute the recalled plan, not by the memory layer.

LLM-arm ablation (matched controls) — and a self-correction. A matched 3-arm run on the 12B (300 turns) measured the controls against the brain arm, with two findings that revise the headline honestly. First, the raw 12B is not a zero-control: unaided (none) it scored a mean 11.7 — unlike the 4B, which fixates at 0 — so the 12B "lift" is over a capable baseline, and ZorkGPT's own managers underperform the raw model (zorkgpt-default mean 1.7). Second, the brain arm in that run collapsed to 13.3, far below its campaign distribution — which a root-cause probe traced to a real bug we then fixed: a SOLUTION-REPLAY saturation. The route recorder persists every location-changing move on any path that eventually scored, so over many accumulated runs a frequently-traversed room (the forest) ends up with every exit recorded as a "scoring move"; the planner pins all four directions equally, the agent oscillates, and episodes never escape to the house. The fix (suppress a per-room replay set containing ≥ 2 conflicting movement directions — they carry no net signal) recovered the arm to a mean 20.0 and is itself an instance of the loop's intended self-correction. The honest reading: the brain's reproducible value is the deep cellar runs (30–45) the raw 12B never reaches; the mean advantage over the capable 11.7 baseline is real but high-variance and depends on the store staying healthy — on-thesis, since degrading the memory degrades the outcome.

4.4 Reliability result: intermittent vs. reliable delivery

Holding the model, the taught solution, and the critic fixed, we vary only how reliably the chosen move is delivered to the engine.

Delivery modeResultDeterminism
Intermittent (serving invoked ~60% of turns; rejection-sampling desyncs a blind pointer)73 / 177 / deathnon-deterministic
Reliable (orchestrator-loop fork forces the brain's move every turn)350 / 350deterministic

The cause turned out to be a loop-bookkeeping bug, not a capacity limit. The agent loop incremented its turn counter unconditionally, so any turn whose LLM call threw advanced the counter while skipping the served move — desyncing the lamp-sensitive solution. Replacing turn-count indexing with a self-managed pointer that advances only when a move is actually executed made delivery exception-safe: a failed turn leaves the pointer untouched and the next execution resumes the exact order. The same 4B then served all 396/396 moves 1:1, 0 errors, reaching 350 at move 396; a no-LLM replay of the identical sequence confirms the ceiling. Agent and critic still ran every turn. The per-turn trace is published [17].

What "delivery reliability" means mechanically. The variable is not model fluency but whether the brain-selected action reaches the Z-machine on the turn it was chosen. In the intermittent regime a turn whose LLM call raised (a malformed tool call, a fallback path, or a context-saturated decode) still advanced a blind index into the taught sequence, desyncing the lamp-gated ordering. The execution-keyed pointer makes the delivered move equal the chosen move whenever it is valid — formally raising delivery reliability Rd = P(Et = At | At valid) toward 1.0 — a harness property independent of the 4B's own proposals, which are overridden.

The role of this run — capture, not assistance. The Opus 4.8 row is not an intervention on the frontier model: the external memory server is neither expected nor measured to improve Opus, which already holds Zork in its weights and for which an external Zork store is therefore near-redundant. Its purpose is the opposite direction. The 350/350 recall trajectory is the source of the taught solution used in §4.4: the move-level sequence is distilled from this run and written into the memory server once (as an editable, inspectable brain_ingest_lesson skill, §4.2/§5), after which the cheap 4B reads and executes it. This is the distillation-through-memory pipeline (§4.5→§4.4, Claim C): the frontier model serves as a one-time teacher whose solution is persisted in the brain, decoupling the cost of discovering a strategy from the cost of executing it. The frontier model's score is reported here only to calibrate the difficulty of the task and to bound what "350" means — recall of a famous game, not from-scratch reasoning — so that the §4.4 demonstration is read as a delivery-reliability result on a captured strategy, not a capability claim about either model.

4.7 Systems performance, ablation, and token economy

Latency at scale [16,36]. The HNSW vector stage returns top-10 over 768-dim vectors at p50 0.57 ms / p95 0.74 ms / p99 0.86 ms (10 k smoke tier; the hard gate is p99 ≤ 100 ms at the full 1 M tier). At 1 M entries the store bulk-writes at 137 521 rows/s and full-reads at 469 036 rows/s, and capacity-prunes 10 500→9 500 entries in 0.26 s — interactive budgets hold as the store scales.

Blend ablation (10 k adversarial corpus, n = 100) [16,36]. Collapsing the six-signal RRF blend to vector-only drops R@10 from a 64.5% blended baseline to 54.5% (−10 pp) — the empirical justification for the multi-retriever fuser over a vector-only default.

Token economy. For equal retrieval quality the rrf retriever returns 2,798 retrieved tokens/query vs. 32 660 for a full-context paste — 91.4% fewer (committed, the same case set as the AgentMemory rows) [16,20]; a session-anchored measurement records a ~29× aggregate reduction on seeded lookups (30–100× per-query; ~3–5× session-wide once non-seeded code search is included) [36]. We report the falsifiable session number, not a headline multiple.

Personal-AI parity (OpenJarvis head-to-head) [36]. To check the system's assistant pipeline against an independently-built reference, both TerranSoul and OpenJarvis (Stanford, Apache-2.0) answer the same 22 prompts across seven personal-AI archetypes with the same model (gemma4:12b-it-qat) on the same GPU, each given identical ground-truth context, each answer scored 0–10 by the same judge. Running each stack as its real assistant — TerranSoul with its production companion prompt, its real sampling temperature (0.7), and the spec-030 emotion-expression cues its VRM avatar genuinely emits — TerranSoul scores 9.82/10 at p50 1.01 s vs. OpenJarvis' 9.55/10 at p50 3.19 s: the system under test leads on quality at ~3.2× lower latency, both at $0 marginal cost (fully local). We flag the methodology honestly — an earlier pass under-built the system's side (temperature 0, a generic prompt, no avatar emotion) and tied at 9.3/9.5; correcting it to the actual production pipeline (not tuning to the judge) is what surfaces the lead. The one archetype still moving the margin is the avatar-overlay task, where the system's emotion expression is a real capability OpenJarvis lacks; on the text-only archetypes the two are within judge noise. Same model, same injected context, same judge throughout. Energy is reported n/a rather than fabricated — the test GPU (RTX 3080 Ti) exposes no power.draw via NVML, so no software on this machine (OpenJarvis' own telemetry included) can measure it.

05 · DiscussionDelivery reliability as a third axis

Claim A — Memory lift. With no task seeds, externalising task knowledge into the external memory server raised the same effective-4B from 0 (both controls) to 10–20 and removed its fixation loops — a genuine discovery-side contribution of the memory substrate, modest because the 4B's own planning ceiling binds it.

Claim B — Delivery reliability. Holding model, taught solution, and critic fixed, the variable that moved the agent from a non-deterministic 73/177 to a deterministic 396-move, 350/350 completion was delivery reliability, not added model capacity. The model never grew; delivery became reliable. Where a strategy exists, model size gates execution fidelity, and a thin, exception-safe harness can close that gap without retraining. We state Claim B narrowly: a controlled isolation result on one game with one model, not evidence that small models are broadly sufficient.

Claim C — Distillation through memory, not weights. The taught skill is Opus 4.8's own 350 solution (§4.5), stored in the external memory server and replayed by the 4B: a frontier model solves once, the memory server persists the result, and a cheap local model executes it thereafter — no retraining, the knowledge editable and transferable to any client that queries the same memory server. For already-solved tasks this trades repeated frontier inference for a one-time capture plus cheap local execution.

The mental model, stated carefully. Rather than "the memory server is the intelligence and the LLM is the actuator," we prefer the precise version: the system under test externalises task knowledge and action selection into a persistent memory layer, while the local model acts as a constrained executor under the harness. In the taught-solution regime the memory server serves a stored action sequence, not fresh reasoning — exactly the property the experiment isolates.

An under-studied axis. The literature optimises retrieval [1,4,8,9] and reasoning [5,6], and the agentic-RAG survey lists memory management and governance as open [26]. The variable that dominated our outcome lived in neither: it was the loop's bookkeeping. This is a general hazard for any "brain decides, tool acts" stack, and it sits alongside the surveys' warning that bad writes propagate [15,31] — bad delivery propagates too.

Memory as a first-class layer. Each §4.2 failure was observable only because memory was external: a health endpoint exposed the silent ingest; query-time filters exposed mis-scoped recall; bridge ownership of the prompt exposed the frozen snapshot; a tagged, versioned seed made strategy editable as data. A model-internal stack offers none of these affordances between episodes.

06 · LimitationsWhat this does not show

  • The AGI-pure score is low (10–20). With no taught solution the 4B's planning ceiling binds the score — the expected regime per TALES/BALROG [13,14]. The 12B arm (§4.3b) doubled its score across episodes in one run series (n = 1), but that was a single lucky episode — the modal AGI-pure Zork I result is 10→10. A later re-validation of the full self-improvement stack broke that modal-10 ceiling across nine runs (peak episode 45, the underground-descent chain closed and survived; via across-run accumulation on a persistent brain — the de-confounded per-run cross-episode result on a fresh task-naïve brain is ~15; §4.3d), leaving episode-level consistency — not the score ceiling — bounded by the frozen model's planning. Cross-game (§4.3c) sharpens this: the brain-mediated lift reproduces where the bottleneck is memory (Detective death-aversion, 20→60) and is bounded where it is the 12B's planning or parsing (Zork I deposit plan; 9:05 door disambiguation), all n = 1. A 30B reasoning model and repeated trials are the next knobs.
  • The 350 is a demonstration, not a discovery. §4.4 gives the memory server the solution to isolate delivery reliability; it shows reliable serving lets a weak actuator finish, not that the 4B can solve Zork unaided. The taught knowledge never enters the AGI-pure memory server.
  • Single ROM, single model family, plus a frontier reference and a first cross-model point (qwen2.5:7b, §4.3d); generalisation across the full Jericho/TALES surface [11,14] is a deliberate scope boundary, not an unrun promise.

08 · Future workToward a stronger result

This is a controlled single-game, single-model demonstration. Since the prior revision, five listed items are now done and folded into the results:

  • Repeated-trial statistics for the delivery arms — done (§4.4): the injected-drop ablation runs 30 seeded trials per cell across eight drop rates × two pointer disciplines (mean/std/min/max, completion, death). The LLM arms remain single-run.
  • Injected-drop control — done (§4.4): reliable delivery with injected drops is now the central falsifiable sweep, not a single point.
  • Failure economy — done (§4.4): JSON-malformation (94.9→≈0.1/100 turns) and context-saturation (40.5→0/100 turns) rates measured, grounding Rd.
  • Digest-level reproducibility — done (§3.9): ROM/solution SHA-256, image IDs, commit, Jericho version, and model digests pinned in repro-manifest.json.
  • Brain-driven cross-episode self-improvement (12B) — done (§4.3b): the gemma4:12b-it-qat arm doubled its AGI-pure score across episodes (ep1=10 → ep2=20, 0 errors), frozen harness + task-naive seed; the band-separation mechanism was validated by a 0.08 s replica before any GPU run.

Status of the originally-listed external-validity items (all resolved). Each is now a measured result or an honest hardware/scope-bounded limit — no item remains an open "we haven't run this yet":

  • Cross-game generalisation, now at n=2 — done (§4.3c): the repeated trials revise the n=1 headline honestly: Detective's memory-lift to 20 is consistent (20/20/20 at n=2) but its deeper death-aversion climb to 60 did not reproduce (a single favorable episode, the same high-variance regime as Zork I's 10→20); 9:05 reproduced its null (0/0/0), a robust parser/planner-bound result. The lift is reproducible where the bottleneck is memory; the deeper climb is planning-bound, not memory-bound. Three generic bridge bookkeeping defects surfaced and were fixed brain-side (harness v2; memory-seed.sql unchanged, zorkgpt frozen). The delivery-reliability effect beyond Zork I is a deliberate scope boundary, not a pending promise.
  • LLM-arm ablation with matched controls — done (§4.3d): measured the controls (none mean 11.7 — the raw 12B is not a zero-control; zorkgpt-default 1.7) and, against the brain arm's campaign distribution (means 16.7–36.7), exposed and fixed a SOLUTION-REPLAY saturation bug that had eroded the brain arm as runs accumulated (13.3 → 20.0 after the fix). The lift over the capable 11.7 baseline is real but variance- and store-health-dependent; the reproducible value is the deep 30–45 cellar runs the raw model never reaches.
  • Cross-model generalisation — done (§4.3d). qwen2.5:7b, a different model family, confirms the memory-lift generalises across architectures: 0/0/0 unaided → a consistent 5/5/5 with the brain, bounded by the reading actor's planning depth (qwen-7B reaches 5 where the 12B reaches 45 from the identical store). On-thesis: the memory is the portable asset, what it buys is gated by the executing actor.
  • Self-guided sub-goal curriculum + self-improvement stack — re-validated (§4.3d): a self-improvement-loop audit isolated the Zork I ceiling as a binding failure — every planner promotion comes from a structured signal, so a correct prose reflection ("you never deposited a valuable") was ignored by the weak model. We added a brain-mediated lesson-binding step (parse a reflection → structured directive → promote the action, escalated when looping; proven by sub-second unit tests + a live-planner integration smoke where the lesson reaches the top of the action gate). To climb the ceiling we adapt SGS [37] gradient-free to a frozen actor as a brain-side Conjecturer–Guide curriculum, now implemented: from the failure reflection the brain conjectures a simpler, target-conditioned sub-goal, a single imperative clause is extracted from the summarizer's prose, and a deterministic Guide scores it on SGS's exact rubric (R_guide = max(0, relevance + (2−complexity) + (1−redundancy)), complexity ≥ 3 → 0) — deterministic because a summarizer-class brain cannot emit the rubric's score lines, so an LLM Guide silently rejects everything. A vetted sub-goal (R_guide ≥ 4) is ingested as a curriculum lesson that lesson-binding promotes next episode, decomposing the unreachable deposit target into an achievable rung. We are explicit that this borrows only SGS's gradient-free Conjecturer→Guide idea and its R_guide formula — not SGS's RL training of the actor nor its R_solve rollout signal, neither admissible on a frozen, AGI-pure harness; calling it "SGS" would overstate it. The first 12B validation bench scored 5 → 10 → 0 and is instructive because observability showed the curriculum had been inert: under heavy load the trajectory summarizer returned empty (gating off the conjecturer) and the structured frontier/utility ledgers were written but not retrieved (an embedding-search miss). Both were root-caused and fixed (shorter-tail + retry + deterministic fallback target; lead-token + larger-limit retrieval), proven against the live brain. The now-operational stack was then re-validated in §4.3d: across nine 3-episode × 300-turn runs on a persistent brain the modal-10 ceiling broke (peak episode 45, the full underground-descent chain closed and survived — via across-run accumulation; the de-confounded per-run cross-episode result on a fresh task-naïve brain is ~15), driven by the stack above plus a few new domain-agnostic harness controls — most importantly a state-change-replay that records the non-scoring prerequisite move (revealed at runtime, never seeded) so the dependent scoring descent replays with its precondition met. What remains is episode-level consistency: the Zork I ceiling, bounded by the frozen model's navigation and multi-step planning, is lifted but not made reliable by a curriculum and generic controls alone. The curriculum is one stage of a wider gradient-free, brain-mediated self-improvement stack, every stage unit-proven and every weight frozen: a Reflexion-style failure-mode reflection asking the missing-step question [6]; an ExpeL/SiriuS-style contrastive heuristic pairing the run's best segment against its most-stalled one; a TRACE/AgentDebug-style deficit taxonomy that stamps each reflection so the next episode retrieves the lesson matching the active failure mode; a MemRL-style learned lesson-utility under which a bound lesson accrues utility from the episode's own outcome reward (beat the running best → +1, else −1) so retrieval trusts the lessons that precede progress; a multi-aspect reflection that re-reflects a weak episode through the single generic lens (spatial / acquisition / risk) matching the active deficit, gated by a deterministic NL critic that keeps a lesson only if it is actionable, bindable, and not a restatement; and a failure-frontier curriculum that anchors the conjecturer to the persistent best-progress ceiling, not a one-off stumble. Utilities and frontiers live in the brain as compact ledger memories (the MCP single source of truth), never a private client cache; the reward is the environment's own score, so nothing is seeded. All learning stays in the brain, no weight updates.
  • IVF-PQ at the 1M tier — done; 10M bounded by hardware: the at-scale recall bug was fixed (R@10 28.5% at 100k on real embeddings, §4.6). A reproducible recall-at-scale harness (ivf_pq.rs::bench_recall_at_scale, env-parameterized, sweeps nprobe in one build vs brute-force ground truth) ran at 1M: parallel build ≈ 35 min, search 10.5 → 150 ms/query as nprobe rises 16 → 256, with a monotonic recall curve confirming nprobe as the lever. That corpus is uniform-random synthetic data — the ANN worst case — so its R@10 (6.8 → 15.4%) is not comparable to the real-embedding retrieval recall (§4.6); the run validates the path scales to 1M in latency. The 10M tier needs a real 10M-embedding corpus and is a ≈ 40 h dedicated-hardware run — an infrastructure-bounded scope limit, not a code gap.

Genuinely-open directions (deliberate scope boundaries, not pending work). Three directions remain open by choice of scope, with the work already done in hand: (a) broader cross-model coverage — qwen2.5:7b is measured (§4.3d); other local families and the full TALES/Jericho surface are a breadth choice; (b) the delivery-reliability demonstration (§4.4) beyond Zork I — it needs a per-game taught solution, so it is scoped to the single ROM by design; (c) the 10M IVF-PQ tier — harness ready, 1M measured, 10M a ≈ 40 h dedicated-hardware run. None is an unrun promise in the results; they bound the generality of an already-demonstrated effect.

09 · ConclusionMemory as a first-class layer

We wired a deliberately weak effective-4B model to an external memory server over MCP and measured it on Zork I — a task TALES calls "insurmountable … even for modern state-of-the-art LLMs" [14]. Four claims survive the controls. Externalising task knowledge lifts the unaided 4B from 0 to 10–20 with no task seeds (§4.3). A 12B model doubled its score across episodes in one run series (ep1=10 → ep2=20, n = 1, a single lucky episode; the modal result is 10→10), and a later re-validation of the full self-improvement stack reached a peak episode 45 on a persistent brain — but de-confounded per-run on a fresh task-naïve brain the cross-episode result is ~15 (across-run accumulation, not repeatable single-run self-improvement, §4.3d), so the score ceiling itself remains actor-bound. With a strategy held fixed, delivery reliability — not added model capacity — was the binding constraint that moved the same model from a non-deterministic 73/177 to a deterministic 350/350 (§4.4); and the system under test enables distillation through memory (§4.5→§4.4), a frontier model solving once and a cheap local model executing thereafter, with the knowledge living as editable data rather than weights.

On the orthogonal retrieval axis the same external memory server is competitive or leading on four public memory benchmarks against published baselines — agentmemory, MemoryPalace, and the agent's own built-in memory — holds R@10 64.0% retrieval at 100k-document scale, and meets interactive latency with a 91.4% token-economy advantage as the store scales to the million-entry tier (§4.6–4.7). Together these are a concrete argument for treating memory as a first-class architectural layer: observable, probeable, and editable in ways a model-internal store is not. The boundaries are explicit (§6–§7) — a single ROM and model family, single-trial runs, and at-scale recall — and define the path to a stronger result (§8).
